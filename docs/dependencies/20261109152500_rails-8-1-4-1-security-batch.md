## Dependency

- rails / actionpack / actionview / activestorage / activesupport / actionmailbox (CI locks were 8.1.3.1 and 7.2.3.2/7.2.4)
- Now: root and rails8* locks on 8.1.4.1; rails80 appraisal on >= 8.0.5.2
- sqlite3 (was 2.9.6, now >= 2.10.2) in Gemfile and Appraisals
- rails80 pins json ~> 2.21, >= 2.21.2 (ActiveSupport 8.0 still passes quirks_mode; json 3 removed it). rails8* stay on json 3.1.0.
- Transitive security bumps: rack >= 3.2.8, nokogiri >= 1.19.7, loofah >= 2.25.3, crass >= 1.0.8, addressable >= 2.9.2, rails-html-sanitizer >= 1.7.2
## Symptom

`bundler-audit` failed on every lockfile after the 2026-11-04 Rails security batch and related rack/nokogiri/loofah/crass/sqlite3 advisories. Dependabot alert #94 remained open for crass <= 1.0.7.

## Evidence

- Commands: `bundler-audit check --update` on Gemfile.lock and gemfiles/*.gemfile.lock; `bundle outdated`; `gh api repos/amkisko/data-migration.rb/dependabot/alerts`
- Rails advisories (examples): GHSA-f3w6-w445-fwh9 (critical Active Storage), GHSA-v924-7rp8-4mxh (high Active Storage), GHSA-8474-xrp6-wh69 (high safe_constantize), GHSA-wm3x-v3qw-4jh3 (high Strong Parameters), plus Action View XSS and Action Pack mediums. Patched versions listed as `~> 8.0.5, >= 8.0.5.2` and `>= 8.1.4.1` only. No 7.2 patched line in ruby-advisory-db.
- This gem calls `safe_constantize` in `DataMigration::Job` when loading a migration class name (hot-path transitive activesupport).
- sqlite3 GHSA-4fqr-96q8-xrfx: query truncation for strings >= 4 GiB; patched >= 2.10.2. Dev/test only in this repo.
- crass GHSA-pq4g-8rxf-4g29 / Dependabot #94: CSS sanitizer bypass; patched >= 1.0.8.

## Suggested fix

Upgrade CI locks to Rails 8.1.4.1 / 8.0.5.2+, sqlite3 2.10.2+, and the transitive patched gems. Replace the unpatched rails72 appraisal with rails80.
